# claude-tg-starter

Turn-key старт для **власного персонального Claude Code Telegram-агента** — self-hosted, на твоїй підписці Claude. Розгорнув один раз, далі **налаштовуєш усе через самого бота** — без інженера.

## Що всередині коробки
- Claude Code агент у Telegram (голос, файли, зображення, PDF)
- Генерація зображень (`gpt-image-2` через Codex) з правильними правилами типографіки
- Деплой на Vercel (вебсторінки / звіти)
- Пам'ять Obsidian-vault + pre-search індекс (агент знає, що в нього в пам'яті)
- Стійкість: self-kill guard, healthcheck, format-enforcer, миттєвий ack — бот не падає й не німіє
- Опційний multi-user режим: незалежні Telegram-чати працюють паралельно; кожна приватна гостьова розмова і кожна група мають ізольовану resumable-сесію
- **Self-service:** власник налаштовує бота прямо з чату — додає людей (pairing), змінює налаштування, allow-list, пише файли. Безпечно (тільки власник)
- Корисні скіли з публічних маркетплейсів: `superpowers` (process-скіли), `frontend-design`, + наші (codex-imagegen, vercel-deploy, research, analyze-video)

## Розгорнути

**Найпростіше — руками свого агента:** відкрий Claude Code у цій теці й напиши «встанови мені асистента» (див. [QUICKSTART.md](QUICKSTART.md)). Агент сам пройде встановлення за ранбуком і проведе тебе по кроках.

**Ставиш сам (або ти — агент-установник): твій ранбук — [DEPLOY.md](DEPLOY.md).** Це повна послідовність (~7 фаз, по порядку, після кожної — verify):
```
Фаза 1   база системи (пакети, bun, node)
Фаза 2   Claude CLI + ВХІД за підпискою власника   ← «мозок» бота, без нього не працює
Фаза 3   розкладка кіта (onboard.sh / install-core) + Telegram-плагін (3c) + скіли (3d)
Фаза 4   запуск (systemd)
Фаза 5-7 стійкість · опції (голос/зображення/календар/Vercel) · smoke-тест (VERIFY.md)
```

> ⚠️ **Мозок бота = підписка Claude власника.** Вхід робить хелпер `claude-login`: він друкує URL, власник відкриває його у браузері, входить своєю Claude Max-підпискою й надсилає код (пароль НЕ вводиться). Це Фаза 2 — найважливіший крок, і він **окремий** від `onboard.sh`.

**Що робить `onboard.sh` (і чого НЕ робить):** це інтерактивний помічник для ОДНІЄЇ фази (конфіг ядра, Фаза 3b) — питає ім'я агента / власника / токен бота / TZ, пише `agent.env` (chmod 600) і запускає `install-core` (юзер, теки, рендер персони, секрети, крон). Ідемпотентно, з валідацією вводу й прихованим введенням секретів. Він **НЕ** ставить сам Claude, **НЕ** логінить підписку, **НЕ** ставить плагін/скіли й **НЕ** піднімає бота — це сусідні фази з DEPLOY.md. Після нього бот ще не відповідає.

```
ssh root@<SERVER>
git clone https://github.com/kgnvsk/claude-tg-starter /opt/claude-tg-starter
cd /opt/claude-tg-starter && bash onboard.sh   # Фаза 3b; далі — за DEPLOY.md
```

## Self-service — головна фішка
Після деплою власник керує всім із Telegram-чату:
- «додай @user у доступ» → бот додасть (pairing, тільки за командою власника)
- «зміни налаштування X» → бот править свій settings
- «запам'ятай правило Y» → бот дописує свою персону

Без другого інструмента, без інженера.

## Опційний multi-user режим

Увімкни `MODULE_MULTI_USER=1`, якщо боту мають писати багато людей. Один durable receiver записує Telegram-апдейти, а bounded dispatcher паралельно обробляє незалежні чати. Приватні чати мають окремі сесії; усі учасники однієї групи ділять сесію цієї групи. Неактивні сесії — це записи в SQLite, а не фонові процеси.

Адміни визначаються лише за числовими `ADMIN_CHAT_IDS` і в приватному чаті зберігають звичайні можливості агента власника. Гості не можуть читати vault власника, змінювати агента/сервер або користуватися приватними MCP-інструментами. За замовчуванням доступ публічний; invite-only режим і відкат однією командою описані в [гайді модуля](modules/multi-user/README.md). Модуль вимкнений за замовчуванням і несумісний з `MODULE_TRANSPORT_DAEMON=1`.

## Безпека
Зміни allow-list / налаштувань / pairing відбуваються ТІЛЬКИ за командою з чату власника (його chat_id). Будь-хто інший, хто напише боту, ніколи не додається автоматично. Секрети живуть у `agent.env` (він у `.gitignore`) — у репозиторій не потрапляють.

## Склад
- `onboard.sh` · `assets/install-core.sh` — онбординг / встановлення
- `assets/` — bin, skills (наші), agents, systemd, templates, vault-skeleton
- `modules/` — опц. аддони (transport-daemon для макс. стійкості, vault-web тощо)

Побудований на тій самій перевіреній архітектурі, що й бойові асистенти. Сторонні скіли (superpowers, frontend-design) ставляться з їхніх публічних маркетплейсів, а не бандляться в код.

## Windows (WSL2) — beta

Кіт розрахований на Linux VPS, але запускається і локально на Windows через WSL2:

1. PowerShell від адміністратора: `wsl --install -d Ubuntu` → перезавантаження → при першому запуску Ubuntu задай ім'я користувача й пароль.
2. Увімкни systemd всередині Ubuntu: `printf '[boot]\nsystemd=true\n' | sudo tee /etc/wsl.conf`, потім у PowerShell `wsl --shutdown` і відкрий Ubuntu знову.
3. Далі — звичайний шлях VPS: `sudo -i`, клонуй кіт і запускай `bash onboard.sh`.

Обмеження: бот працює, поки запущений WSL (ноутбук увімкнено). Статус: beta — основний перевірений шлях лишається Linux VPS.
