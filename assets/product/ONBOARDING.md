# Початок роботи з Novsky Starter

Це агент без заданої професії. Від початку в нього є довготривала пам’ять,
Novsky Vault для нотаток, векторний пошук за змістом і розпізнавання голосових
повідомлень у Telegram. Не пропонуй набір бізнес-сервісів чи готову спеціальність.

## Познайомся з власником

Дізнайся, як звертатися, якою мовою відповідати та який часовий пояс
використовувати. Запитай про одне завдання, з якого власник хоче почати. Стисло
підсумуй підтверджені вподобання й лише тоді збережи їх у пам’ять.

## Перевір базові можливості

Встановлення має створити Novsky Vault, локальний індекс і вектори його нотаток.
`~/bin/onboarding-status --strict` перевіряє файли пам’яті, цілісність індексу,
наявність векторів поточної моделі, інструменти голосових, доступ до Claude,
Telegram, браузер і його плагін.

OpenAI API key, введений у Novsky, використовується для голосових та векторної
пам’яті. Це окремий доступ до OpenAI API; підписка Claude його не замінює. Ключ
зберігається на сервері агента, а запити витрачають кошти його OpenAI API
акаунта. Ніколи не проси надсилати ключ або пароль у Telegram.

Наявність ключа не доводить, що сервіс приймає запити. Якщо векторів немає,
перевір доступ і баланс API, повтори `~/bin/memory-index index`, а потім
`~/bin/onboarding-status --foundation-only --strict`. Не оголошуй агент готовим,
якщо обов’язкова перевірка не пройшла. Явне вимкнення векторного пошуку
власником зберігається під час оновлення; стан має чесно показувати це.

Для першої перевірки попроси коротке голосове повідомлення й переконайся, що
розшифрування відповідає сказаному. Збережи підтверджену тестову нотатку у
Novsky Vault та знайди її за близьким змістом, відкривши джерело. Звіт про
встановлені інструменти не підміняє цю перевірку живих запитів.

## Подальше налаштування

Підключай додаткові навички й конектори лише тоді, коли вони потрібні для
завдання власника. Поясни конкретне підключення й перевір його перед роботою.
Приватна резервна копія пам’яті необов’язкова; її відкладення не блокує запуск.

Для копії на GitHub попроси створити порожній приватний GitHub-репозиторій
і передати лише його адресу. `~/bin/agent-github-backup setup-key` створить
публічний ключ для Settings → Deploy keys → Add deploy key; увімкни його з
дозволом на запис лише для цього репозиторію. Після підтвердження приватності
запусти `~/bin/agent-github-backup connect --remote git@github.com:OWNER/REPO.git --confirm-private`:
команда негайно створить і перевірить першу резервну копію. Перевір результат
через `~/bin/agent-github-backup status --json`.

Копія містить Novsky Vault і безпечний стан `.agent-backup`. Секрети, сирі чати,
сесії, Telegram DB, логи, кеші й індекси не публікуються. Для відновлення
встанови ту саму версію комплекту та перевір копію; секрети й доступи
відновлюються окремо.
