# Субагенти цього бота

Тут живуть **субагенти** — спеціалізовані підвиконавці, яких бот викликає
для окремих завдань (дослідження, рев'ю коду, будь-що). Це нативна можливість Claude Code:
**один `.md`-файл = один агент.** Їхні токени йдуть на ту саму підписку, що й у бота —
окремий тарифікований пул не використовується.

## Як додати свого агента

1. Створи файл `ім'я-агента.md` у цій папці (`~/.claude/agents/`).
2. Заповни його за форматом нижче.
3. Бот побачить нового агента сам, без перезапуску.

## Формат файла

    ---
    name: ім'я-агента          # обов'язково: малі літери й дефіси
    description: Коли мене кликати — 1-2 речення. Бот читає це й сам вирішує делегувати.   # обов'язково
    tools: WebSearch, WebFetch, Read, Grep, Glob   # необов'язково: через кому (НЕ список). Порожньо = усі інструменти.
    model: opus               # завжди opus: субагент відповідає за якість так само, як ти
    ---

    Тут — системний промпт агента: хто він, як працює, що повертає.

Обов'язкові лише `name` і `description`. Решта — необов'язково.

## Свій помічник з виду роботи

Для роботи, що повторюється (підбір, пошта, сайт, звіти), бот тримає свого помічника з правилами власника саме про неї.
Такі файли веде сам бот: огляд пам'яті додає в них нові постійні правила власника, а бот — одразу, коли власник
сказав правило в розмові. `worker.md`, `researcher.md` і ролі комплекту не чіпай: їх оновлює комплект.

    ---
    name: cars
    description: Підбір авто для клієнтів — пошук, перевірка, картка варіанта. Клич для будь-якого підбору чи оцінки авто.
    disallowedTools: mcp__plugin_telegram_telegram, mcp__corporate
    model: opus
    permissionMode: bypassPermissions
    ---
    Ти ведеш підбір авто для власника. Розмови головного агента не бачиш; правила власника, його профіль і правила
    комплекту для помічників отримуєш на старті.

    ## Правила власника
    - 18.11.2026 14:05: картку показуй лише після перевірки історії авто.

    ## Як це робиться тут
    - 19.11.2026: ціни ринку — з двох майданчиків, не з одного.

Щоб правила не стали смітником:

- **Правило власника — лише його постійні слова** про цю роботу («завжди», «ніколи», «не так, а так»), близько до
  того, як він сказав, з датою й часом його повідомлення. Побажання до одного завдання — не правило. Свого як
  його не записуй.
- **Одне правило — в одному місці:** що стосується всієї роботи — у профілі (`USER.md`), що одного виду роботи — у
  його помічнику.
- **Нове слово власника замінює старе правило**, а не лягає поруч; пізніше датоване правило старішим словом не
  замінюй.
- **«Як це робиться тут»** — твої перевірені знахідки (де лежить доступ, яке джерело відповідає), окремо від правил
  власника.
- **Правило власника не викидай і не скорочуй заради місця.**
- Новий помічник — лише під роботу, що повторюється, і коли жоден наявний її не покриває.

Кожна зміна такого файла зберігається: попередні версії лежать у `~/.local/state/memory-v2/helpers-history/<ім'я>/`.
Власник просить повернути чи прибрати правило — зміни файл і скажи, що саме змінив.

## Як бот їх викликає

- **Сам**, коли твоє завдання збігається з `description` агента.
- **За ім'ям**, якщо попросиш прямо: «візьми researcher і збери інформацію про …».

## Важливо про ліміт

Кожен субагент — повноцінна підсесія. Працює на підписці (не на окремому
платному пулі), але **витрачає лімітне вікно швидше** за звичайний чат. Для легких завдань
залишай агенту `model: opus` — субагент потрібен заради зв'язку, а не заради економії.
