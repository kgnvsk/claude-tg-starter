# Telegram formatting — детальний гайд

Деталі до правил з `CLAUDE.md`:
- «Довгі відповіді-перерахування → markdownv2 + коротко»
- «reply-tool сам екранує — не роби `~/bin/tg-escape` вручну»

## Базові правила

- MarkdownV2 синтаксис: `*жирний*` (одна зірочка, НЕ дві), `_курсив_`, `` `code` ``, `[label](url)`.
- Максимум 4096 символів у повідомленні (плагін чанкає автоматично).
- Довгі code blocks TG погано форматить — скорочуй або роби summary.
- Файли: спочатку скопіюй у `~/telegram-outbox`, а в reply передай абсолютний
  шлях на кшталт `files: ["/home/claude/telegram-outbox/report.pdf"]`.

## КОРІННЕ РІШЕННЯ: сирий markdown для reply-tool

З 2026-06-23 у `server.ts` telegram-плагіна: reply-tool за дефолтом використовує `format: "markdownv2"` І завжди сам проганяє твій `text` через `~/bin/tg-escape` перед відправкою. Це знімає з тебе escape повністю.

**Що робити:**
- Написати `text` з НАМІРЕНОЮ розміткою (`*bold*`, `_italic_`, `` `code` ``, `[label](url)`) і СИРИМ звичайним текстом — БЕЗ жодного `\`.
- Передати в reply з `format: "markdownv2"` (або без format — дефолт).
- Tool сам все заекранує один раз коректно.

**Приклад:**
```
reply(text: "*Завершено.* Hook встановлено.\n\n*Що зробив*\n- /home/claude/bin/x\n- (matcher: reply)",
      format: "markdownv2")
```

Tool відправить це так, що `Завершено` і `Що зробив` будуть жирними, крапки/дужки/дефіси заекрануються автоматично.

## АНТИ-ПАТЕРН (це БАГ)

Проганяти текст через `~/bin/tg-escape` САМОМУ перед reply. Tool потім прожене ВДРУГЕ → подвійний escape → `\\.` `\\-` → парсер падає → fallback теж падає → летить plain text з літеральними `*`.

Саме цей сценарій зламав форматування 2026-06-23 (msg 4222, 4225, 4228).

**Жорстке правило:** у `text` для reply НІКОЛИ не з'являється зворотний слеш, поставлений мною. Тільки розмітка (`*bold*` тощо) + звичайний текст (крапки, дефіси, дужки, плюси, знаки оклику — голі). Екранування робить reply-tool. Впіймав себе на `\` в payload — стоп, переписати без нього.

## Коли `~/bin/tg-escape` все ж потрібен ВРУЧНУ

Тільки якщо будую markdownv2 текст для якогось ІНШОГО каналу доставки — curl напряму в Bot API, claw-publish, і т.п. Там немає авто-escape. Для `mcp__plugin_telegram_telegram__reply` — НІ.

## Якщо markdownv2 зовсім не потрібен

Коротка відповідь, чистий ASCII без структури: передай `format: "text"` явно — plain без будь-якого escape.

## Шаблон структурного TG-повідомлення (list-like)

Для будь-якої відповіді з перерахуванням 5+ пунктів (ClickUp-завдання, календар, статистика, список tools):

```
📋 *Заголовок* (контекст)

⚠️ *Гарячі точки:*
• ключове 1
• ключове 2

🎯 *Секція 1* - N завдань

_статус 1:_
• завдання
• завдання

📊 *Статистика:*
• *N* у статусі X
```

Правила:
- Жирний заголовок ЦІЛКОМ (з емоджі всередині bold).
- Порожній рядок між секціями замість `---` чи `━━━`.
- Коротко — не полотном. Довше 8-10 рядків → майже завжди можна скоротити вдвічі.

## Історія помилок

- 2026-04-23: MarkdownV2 bold = ОДНА зірочка `*text*`, не `**text**`. Користувач вказав тричі, поки це закріпилося.
- 2026-06-23: Подвійний escape через tg-escape перед reply → парсер падав, летів plain text. Три повідомлення поспіль зіпсовані.
