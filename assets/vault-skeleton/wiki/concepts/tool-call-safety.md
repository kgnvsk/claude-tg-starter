# Tool-call safety — коли аргумент іде через файл

Деталі до правила з `CLAUDE.md`: «великий/складний контент — через файл, не inline».

## Чому це критично

На Opus 4.7/4.8 якщо в аргумент tool-вызова попадає великий/складний контент (вкладені лапки, переноси рядків, код, JSON, промпт) — серіалізація tool_use ламається, виклик іде ТЕКСТОМ (`<invoke name=...>` як текст), НЕ виконується. Далі каскад: ламається все підряд, включно з `reply` → бот мовчить. Не лікується на льоту, тільки скидом контексту.

Цей факап клав агент не раз — треба уникати повністю.

## Що вважається "великим/складним"

Якщо ХОЧ ОДНЕ — значить у файл:

- лапка всередині лапки (`"... '...' ..."`);
- перенос рядка / багаторядковість;
- `$(...)` з логікою, backtick, heredoc (`<<EOF`);
- `{ }`, `=>`, стрілочні функції `() => {...}` (JS);
- код в `-c`/`-e`/`-p` (`python3 -c`, `node -e`, `perl -e`…);
- тіло JSON / HTML / JS / великий промпт;
- аргумент довше ~200 символів.

## Як ПРАВИЛЬНО (універсально)

1. `Write` контент у файл: `/tmp/x.py`, `/tmp/x.sh`, `/tmp/x.js`, `/tmp/x.json`, `/tmp/prompt.txt`.
2. КОРОТКА команда споживає файл:
   - Python: `python3 /tmp/x.py`
   - Bash: `bash /tmp/x.sh`
   - Node: `node /tmp/x.js`
   - codex/картинки: `codex exec ... "$(cat /tmp/prompt.txt)"`
   - curl з JSON: `curl ... -d @/tmp/body.json`
   - playwright browser_evaluate: не інлайнити JS-стрілку з лапками; тримати функцію короткою, складне — у файл.

## WRONG → RIGHT

- ❌ `codex exec -m gpt-5.5 "Use gpt-image-2 ... довгий промпт з лапками ..."`
  ✅ `Write /tmp/prompt.txt` → `codex exec -m gpt-5.5 "$(cat /tmp/prompt.txt)"`
- ❌ `python3 -c "import json; d=json.load(open('x')); print(d['url'])"`
  ✅ `Write /tmp/x.py` → `python3 /tmp/x.py`
- ❌ `curl -X POST ... -d '{"a":"b","c":{"d":1}}'`
  ✅ `Write /tmp/body.json` → `curl -X POST ... -d @/tmp/body.json`

## Чек-ліст перед кожним Bash/tool-викликом (1 секунда)

> В аргументі є: лапка-в-лапці? перенос рядка? `$()`/backtick? `{}`/`=>`/`<<`? код/JSON? довше ~200 символів?
>
> ХОЧ ОДНЕ ТАК → СТОП: `Write` у файл, потім коротка команда. ВСЕ НІ → можна слати.

## Якщо все ж зірвалося

Побачив «malformed and could not be parsed» АБО свій виклик текстом з `<invoke>`: НЕ повторюй той же виклик — це каскад. Перепиши через файл. Дві помилки поспіль → одним `reply` скажи владельцу «глюк формату викликів» і чекай /compact.
