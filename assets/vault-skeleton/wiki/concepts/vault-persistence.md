# Vault persistence — детальні критерії

Деталі до правила з `CLAUDE.md`: «пиши в vault тільки переиспользуване знання».

## Основний тест

**"Повернемось ми до цього через тиждень/місяць?"** Якщо ні — не пиши.

## ПИШЕМО в vault

- Інтеграції/інфра (нові API, wrappers, скрипти для переиспользування) — приклад: Monobank API wrapper, як викликати.
- Гайди/чек-листи для повторення — приклад: розгортання Claude Code+Telegram на VPS.
- Правила форматування/стилю, на які наступили граблі — приклад: MarkdownV2 bold = одна зірочка.
- Факти про сім'ю (імена, аліаси, дні народження, контакти).
- Бізнес/клієнти (компанії, ціни, проекти, рішення).
- AI-методологія/інсайти (що працює, що ні).
- Інфраструктурні рішення (конфіги, хуки, скрипти).

## НЕ ПИШЕМО в vault

- Канал-пости (опублікували і забули).
- Sport/esports/новини запити.
- Разові покупки для родичів.
- Курси валют, погода, маршрути.
- Транскрипти голосових без action-рішень.

## Куди писати

- `wiki/log.md` — timestamp + 3-7 буллетів, нові записи ЗВЕРХУ.
- `wiki/entities/` — люди, компанії, проекти.
- `wiki/concepts/` — патерни, методи, інтеграції, гайди.
- `wiki/tasks/active.md` — поточні задачі.
- `wiki/sources/` — зовнішні посилання на повторне використання.
- `wiki/hot.md` — Recent Changes + Last Updated якщо важливе.

## Автоматизація

Хук `vault-sync` (PostToolUse) автокоммітить при Write/Edit — просто пиши, git-ом опікуватись не треба.
