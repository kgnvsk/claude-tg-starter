# Progressive status — детальний гайд

Деталі до правила з `CLAUDE.md`: «>1 крок або >10 сек → перший reply "🔄 Взяв: ...", проміжні фази через edit_message, фінал новим reply».

## Правила

- Задача >10 сек або >1 tool-виклику — ПЕРШИМ ділом, ДО роботи, короткий `reply`: «🔄 Взяв: <у двох словах>». Пінг — владелец одразу бачить, що ти стартанув.
- Довгі задачі (>1 хв) — проміжні фази через `edit_message` ПЕРШОГО статусу (без push-notification, не спамить).
- Фінал — завжди новим `reply` (щоб точно прийшов пінг на телефон).

## Приклад на ділі

```
[User] Зроби КП для клієнта на $10k з Apple стилем.
[Bot] 🔄 Починаю роботу...                          ← initial reply, msg_id=42
[Bot→edit msg 42] 📝 Пишу HTML верстку...
[Bot→edit msg 42] 🖨️ Конвертую в PDF через Chromium...
[Bot→new reply] ✅ Готово, у вкладенні               ← new reply з PDF attach
```

## Приклади фаз для edit_message

- «📝 Пишу HTML верстку...»
- «🎨 Генерую картинку...»
- «🖨️ Конвертую в PDF...»
- «📚 Читаю vault...»
- «🌐 Шукаю в інтернеті (раунд 2/3)...»
- «📄 Читаю PDF»

## Опціонально: react на оригінальне повідомлення

Для дуже довгих задач (>1 хв) — реагуй на оригінальне повідомлення користувача різними емодзі: 👀 → 🤔 → ✅.

## Коли НЕ використовувати

- Короткі відповіді (<5 сек генерації) — просто відповідай.
- Прості питання — не спамити статусами.
- **Голосові транскрипції без аналізу** — швидко (~2 сек download + ~5 сек transcribe), не треба. Це виняток з правила «>1 крок = пінг», бо кроки короткі і предсказуемі.
- Якщо після транскрипції йде АНАЛІЗ (не просто «транскрибуй»), і аналіз >10 сек — тоді пінг ставиш ПІСЛЯ транскрипту, перед аналізом.

## Технічна деталь

`edit_message` не шле push-уведомлення на телефон користувача. Це добре для проміжних статусів (не дратує), але фінальний результат ЗАВЖДИ через новий `reply` — щоб точно отримав пінг.
