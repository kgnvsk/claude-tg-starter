# auto-publisher — развернуть авто-паблишер (StreamPost)

Готовый пакет: **`github.com/kgnvsk/superpost`** (private). Лёгкий python-сервис: Telethon (юзер-сессия читает источники) + Bot API (публикует) + Claude (переписывает). Конфиги (`sources.json`/`filters.json`/`style.md`) — hot-reload, без рестарта. Один бот делает и публикацию, и админ-команды (по whitelisted user_id).

## Архитектура (объясни это пользователю)
- Отдельный сервис (systemd `streampost`), но **публикует ТЕМ ЖЕ ботом, что и сам агент** — переиспользует токен агента. **Отдельного бота НЕ создаём.** Он только **шлёт** в канал (`sendMessage`, апдейты не поллит) → с чат-ботом агента НЕ конфликтует (один и тот же токен ок, пока второй процесс не делает getUpdates).
- Нужно ровно одно действие: **добавить бота агента админом (право Post Messages)** в целевой канал. Токен уже лежит на боксе — в `.env` агента.
- **Источники читает юзер-сессия** (твой личный Telegram-аккаунт, API ID/Hash с my.telegram.org) — ботом чужие каналы читать нельзя.
- **Рерайт** через Claude Max (дефолт) или Anthropic API-key.
- *(Standalone без агента-бота на боксе — только тогда создавай бота у @BotFather.)*

## Онбординг — В ЧАТЕ, пошагово (НЕ гони install.sh молча)
Веди диалогом, по одному блоку, дружелюбно. Собери:

1. **Цель и ниша.** Про что канал? (AI-новости / крипта / маркетинг / нишевое). Язык постов? Тон (живой/ироничный vs сдержанный экспертный)?
2. **Источники.** Попроси:
   - TG-каналы-источники (@username через запятую) — из них читаем.
   - RSS/сайты (дай примеры: TechCrunch, The Verge, блоги — у большинства есть `/feed`/`/rss`). Помоги найти RSS сайта, если дал только ссылку.
3. **Целевой канал** (бот = сам агент, нового НЕ создаём):
   - Создай/возьми канал и **добавь бота агента админом** с правом «Post Messages». Это тот же бот, через которого пользователь общается с агентом. (Повтори: без прав админа публикация молча падает.)
   - Узнай **channel ID**: репостни любой пост канала боту **@userinfobot** → покажет `-100…`.
4. **Ключи.** API ID + API Hash (**my.telegram.org** → API development tools) — для юзер-сессии, читающей источники. Свой **user_id** (@userinfobot). LLM: `claude-max` (подписка, дефолт). Токен бота НЕ спрашивай — берётся токен самого агента.
5. **Стиль (генерик — спроси и напиши сам).** По нише/языку/тону из шага 1 составь `configs/style.md`. Покажи пользователю 1-2 примера постов ДО запуска, чтобы согласовать формат. Опорный эталон (адаптируй, НЕ копируй язык): режимы **LIGHT** (80%, живее, ирония, эмодзи-буллеты) / **THINK** (20%, сдержанно); заголовок = 1 эмодзи + `<b>…</b>`; первое предложение = конкретный факт; лид = суть фичи, не метрика; только HTML (`<b><i><a><blockquote><code><pre>`), НИКАКОГО markdown; код/CLI — в `<pre><code class="language-bash">`; **только короткий дефис, НИКОГДА длинное тире** (главный маркер AI-текста); структуру варьируй между постами.

## Шаг 0 деплоя — доступ к пакету (пакет `superpost` приватный)
Проверь, видит ли бокс репо: `git ls-remote https://github.com/kgnvsk/superpost >/dev/null 2>&1 && echo OK || echo NO_ACCESS`.
- **OK** → деплой ниже.
- **NO_ACCESS** (сторонний бокс без доступа к kgnvsk) → НЕ клонируй вслепую. Скажи пользователю в чате прямо, по-человечески, примерно так: «Чтобы поднять автопаблишер, нужен доступ к приватному репозиторию StreamPost. Как получить: **(а)** пришли мне свой GitHub-username — передам владельцу, он выдаст тебе read-доступ к `kgnvsk/superpost` (или поставит deploy-key на этот бокс); либо **(б)** владелец сделает репо публичным. После этого продолжим установку.» Дождись доступа, потом деплой. (raw `curl|bash` для приватного репо НЕ работает — только `git clone` с доступом.)

## Деплой (после согласования и доступа)
Сначала проверь, что автопаблишер тут ещё НЕ крутится (чтобы не задвоить публикацию тем же ботом): `systemctl is-active streampost auto-publisher 2>/dev/null`. Если уже активен — не разворачивай второй, а правь конфиги существующего.
```bash
git clone https://github.com/kgnvsk/superpost /opt/streampost && cd /opt/streampost
# токен агента (подставь на вопрос про bot token, НЕ создавай нового бота):
grep '^TELEGRAM_BOT_TOKEN=' ~/.claude/channels/telegram/.env
bash install.sh      # спросит API ID/Hash, bot token (→ токен агента ↑), channel ID, user_id, LLM
```
`install.sh` пишет `.env` + `configs/admin.json`, ставит зависимости, systemd `streampost`, запускает. Затем **впиши источники** в `configs/sources.json` и **стиль** в `configs/style.md` (hot-reload — рестарт не нужен). Ключи остаются в `.env` на боксе пользователя, никуда не уходят.

⚠️ **Репо `superpost` приватный** → боксу нужен git-доступ к `kgnvsk` (у боксов владельца есть). `raw.githubusercontent … | bash` для приватного репо НЕ работает (404 без токена) — только `git clone`. Сторонний клиент без доступа к kgnvsk — сначала выдать ему доступ к superpost или сделать репо public.

⚠️ **Человеческий шаг (назови его явно):** `create_session.py` логинит юзер-сессию Telethon — Telegram пришлёт **код в приложение**, его вводит ПОЛЬЗОВАТЕЛЬ. Без этого источники не читаются. Это единственная часть, где нужен человек в реальном времени.

## Проверка (обязательно до «готово»)
1. `systemctl is-active streampost` → active.
2. `journalctl -u streampost -n 40` → видит источники, нет ошибок авторизации.
3. Дождись/спровоцируй первый пост → проверь, что он реально появился В КАНАЛЕ (бот-админ работает) и в нужном стиле.
4. Покажи пользователю первый опубликованный пост, спроси — правим стиль в `configs/style.md` (hot-reload).

## Частые грабли
- Публикация молчит → бот НЕ админ канала (или нет права Post Messages).
- Источники пустые → юзер-сессия не залогинена (`create_session.py` не пройден) или каналы приватные/не те @username.
- Рекламный шум → правь `configs/filters.json` (стоп-слова, промо-паттерны).
- Длинное тире / markdown в постах → ужесточи правило в `style.md` (HTML-only, только `-`).
